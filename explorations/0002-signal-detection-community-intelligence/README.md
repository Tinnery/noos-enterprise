**启动日期**: 2026-03-18  
**当前阶段**: 阶段 1 - 发现与理解  
**探索状态**: 进行中  
**出版端输出**：Media Works Pilot 002（ai-identity-trust）— 将本探索涉及的信号检测与治理分析转化为面向非专业读者的科普文章

---

## 1. 探索目标

### 1.1 核心问题

**如何通过系统化的信号检测和社区融入机制，在信息成为主流之前捕获弱信号，从而获得行业洞察的先发优势？**

传统的信息收集方式（新闻订阅、社交媒体关注）只能获取已经传播开的信息。当信息到达主流渠道时，早期机会窗口已经关闭。我们需要的是：

- **信号检测**：在 arXiv 引用网络变化、GitHub 低星项目 trending、技术博客"放弃 X 工具"文章、小众论坛重复话题中识别弱信号
- **社区结构分析**：通过社会网络分析（SNA）识别关键人物、信息枢纽、新兴声音、跨社区传播路径
- **实践共同体参与**：通过贡献（PR、技术博客、回答技术问题）真正加入社区，而非旁观
- **反馈循环**：将检测结果与 Exploration 0001 的分类图谱和假设验证闭环

### 1.2 与 Exploration 0001 的关系

Exploration 0001 建立了软件产业分类图谱（`frameworks/software-landscape-taxonomy.md`），但这是静态快照。信号检测系统为其提供**动态更新机制**：

- **Step 2 落地**：分类图谱的 Step 2（AI 影响叠加）需要实时数据输入，信号检测系统提供这些数据
- **假设验证**：HYP-001~005 的验证需要市场信号（如"小企业工作流自动化需求增长"）
- **新假设发现**：弱信号可能揭示分类图谱中未覆盖的新兴类别

## 2. 方法论框架

本探索采用四层架构，从数据采集到决策支持形成闭环：

```

│  Layer 4: 反馈循环层                                      │
│  - 预测准确性追踪                                         │
│  - 决策质量评估                                           │
│  - 方法论迭代优化                                         │
└─────────────────────────────────────────────────────────┘
                           ↑
┌─────────────────────────────────────────────────────────┐
│  Layer 3: 实践参与层                                      │
│  - 社区贡献（PR、技术博客、问答）                          │
│  - 关系建立（与关键人物互动）                              │
│  - 声誉积累（成为可信成员）                                │
└─────────────────────────────────────────────────────────┘
                           ↑
┌─────────────────────────────────────────────────────────┐
│  Layer 2: 社区结构分析层                                  │
│  - 社会网络分析（SNA）                                    │
│  - 关键人物识别（意见领袖、信息枢纽、新兴声音）            │
│  - 跨社区传播路径追踪                                     │
└─────────────────────────────────────────────────────────┘
                           ↑
┌─────────────────────────────────────────────────────────┐
│  Layer 1: 信号检测层                                      │
│  - 数据源接入（arXiv、GitHub、Hacker News 等）            │
│  - 弱信号识别（引用网络变化、低星 trending、放弃叙事）     │
│  - 主题建模与变化点检测                                   │
└─────────────────────────────────────────────────────────┘
```

### 2.1 Layer 1: 信号检测层

**目标**：在信息成为主流之前捕获弱信号

**数据源分层**：

| 层级 | 数据源 | 信号类型 | 采集频率 |
|------|--------|----------|----------|
| 学术层 | arXiv API、Google Scholar | 引用网络变化、新论文主题 | 每日 |
| 开源层 | GitHub API、Stack Overflow | 低星项目 trending、"放弃 X 工具"问题 | 每日 |
| 市场层 | Crunchbase、Product Hunt | 融资事件、新产品发布 | 每周 |
| 社交层 | Twitter/X API、LinkedIn、Reddit | 意见领袖发言、话题热度 | 实时/每日 |

**弱信号识别方法**：

1. **引用网络变化检测**
   - 监控 arXiv 论文引用网络的结构性变化
   - 工具：NetworkX（图分析）、变化点检测算法
   - 信号示例：某篇论文突然被多个不相关领域引用

2. **低星项目 trending 分析**
   - 监控 GitHub 上 10-100 星项目的增长率异常
   - 工具：GitHub API、trending 追踪脚本
   - 信号示例：某项目一周内从 20 星增长到 200 星

3. **"放弃叙事"检测**
   - 监控技术博客、Stack Overflow 中"放弃 X 工具"类文章
   - 工具：文本分类（BERTopic）、关键词匹配
   - 信号示例：多个独立博客同时发布"从 X 迁移到 Y"文章

4. **小众论坛重复话题**
   - 监控 Reddit、Hacker News 中重复出现的主题
   - 工具：主题建模（LDA/BERTopic）、频率统计
   - 信号示例：某话题在 3 个不同 subreddit 中一周内出现 5+ 次

### 2.2 Layer 2: 社区结构分析层

**目标**：识别社区中的关键人物和信息流动路径

**社会网络分析（SNA）维度**：

1. **关键人物识别**
   - **意见领袖**：高影响力节点（PageRank、Betweenness Centrality）
   - **信息枢纽**：连接不同社区的桥接节点
   - **新兴声音**：近期活跃度快速上升的节点

2. **社区结构分析**
   - **社区检测**：Louvain、Label Propagation 算法
   - **跨社区传播**：追踪信息从一个社区到另一个社区的路径和时滞
   - **信息时滞测量**：信号从学术层传播到市场层的时间

3. **工具与方法**
   - **NetworkX**：图构建和分析
   - **Gephi**：可视化（可选，用于报告）
   - **节点中心性指标**：Degree、Betweenness、Closeness、PageRank

### 2.3 Layer 3: 实践参与层

**目标**：通过贡献真正加入社区，而非旁观

**参与策略**：

1. **技术贡献**
   - 提交 PR（修复 bug、添加功能、改进文档）
   - 开源自己的工具（信号检测脚本、数据可视化工具）
   - 目标：在 3 个核心社区建立可见度

2. **知识贡献**
   - 撰写技术博客（分析方法论、工具使用经验）
   - 回答 Stack Overflow 技术问题
   - 在 Reddit/Hacker News 参与讨论

3. **关系建立**
   - 与关键人物互动（评论、转发、合作）
   - 参与社区活动（线上/线下 meetup）
   - 目标：成为可信成员，获得内部信息

**成功标准**：
- 3 个核心社区的可见度（被提及、被引用）
- 至少 1 个 PR 被合并到目标项目
- 至少 1 篇技术博客获得社区反馈

### 2.4 Layer 4: 反馈循环层

**目标**：追踪预测准确性，迭代优化方法论

**追踪指标**：

1. **预测准确性**
   - 提前 6-12 个月识别的趋势中，最终成为主流的比例
   - 误报分析：识别的信号中，未成为趋势的比例
   - 目标：70% 的方向判断有价值

2. **网络位置**
   - 信息时滞：从信号出现到我们捕获的时间
   - 目标：< 7 天（相比主流媒体的报道时间）

3. **社区融入**
   - 3 个核心社区的可见度
   - 被关键人物提及/引用的次数
   - 目标：至少 1 个社区达到"可信成员"地位

4. **决策质量**
   - 基于信号做出的方向判断，最终被验证正确的比例
   - 目标：70% 的方向判断有价值

## 3. 数据源与技术栈

### 3.1 数据源清单

| 数据源 | API/访问方式 | 数据内容 | 采集频率 | 优先级 |
|--------|--------------|----------|----------|--------|
| arXiv | arXiv API | 论文元数据、引用关系 | 每日 | P0 |
| GitHub | GitHub REST/GraphQL API | 项目元数据、star 历史、PR/Issue | 每日 | P0 |
| Hacker News | Firebase API | 帖子、评论、投票 | 每日 | P0 |
| Stack Overflow | Stack Exchange API | 问题、标签、投票 | 每周 | P1 |
| Reddit | Reddit API | 帖子、评论、subreddit 数据 | 每日 | P1 |
| Twitter/X | Twitter API v2 | 推文、用户、话题 | 实时/每日 | P2 |
| Crunchbase | Crunchbase API | 融资事件、公司信息 | 每周 | P2 |
| Product Hunt | GraphQL API | 新产品、投票、评论 | 每周 | P2 |

### 3.2 技术栈

**数据采集**：
- Python（requests、aiohttp）
- API 客户端库（arxiv、github3.py、praw）

**数据分析**：
- NetworkX（图分析）
- scikit-learn（聚类、分类）
- BERTopic（主题建模）
- pandas、numpy（数据处理）

**可视化**：
- matplotlib、seaborn（静态图表）
- plotly（交互式图表）
- Gephi（网络可视化，可选）

**存储**：
- SQLite（本地数据存储）
- JSON/CSV（导出数据）

- 优先使用免费 API 和公开数据源
